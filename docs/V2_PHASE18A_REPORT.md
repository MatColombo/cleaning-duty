# House Care V2 — Phase 18A implementation and test report

**Baseline:** exact Phase 17C updated repository ZIP (`2.0.0-rc.5`). **Output:** `2.0.0-rc.6` on the V2 candidate branch. **Scope:** client-only, transient Character Studio prototype. **No schema, persistence, deployment or Phase 18B implementation.**

## 1. Source inspection and protected invariants

- The source already offers deterministic generator-v2 recipes (`src/visual/procedural/recipe.ts`), authored objects, expressions, poses and a card renderer. It also has a keyboard-focus-trapped accessible `Sheet` component.
- A routine, Action, or entity has no saved visual override. This remains unchanged. Phase 18A does **not** add visual override properties to `WorkspaceData`, backups, app snapshots, Supabase, RPCs, local storage or a task.
- Existing task state transitions, Undo, notification behavior, recurrence, stock, layout and V1/V2 RPCs remain untouched. The Studio is a presentation-only overlay. The V1 client still has no dependency on the new client-only UI.
- The visual generator version stays **2** (advanced deliberately in Phase 17C). The app/service worker candidate version moves from rc.5 to rc.6 to avoid stale PWA bundles.

## 2. Implemented editor behavior

- Opens via **Character Studio** on existing Routine Library Cards, Action Library Cards and selected entities in Home Inspector.
- Always starts with **Artwork: Auto**, showing a deterministic auto-generated card. Entry uses stable synthetic preview-only IDs; previews never issue a task occurrence.
- Curated live inputs: 39 built-in real object/character primitives; 12 authored expressions; independent known eyes/mouth/brows; 12 poses; five glove/hand types; bounded scale (75–125% in 5% steps); three proportions; seven prop options; nine scenes; four palette variants; four finite motion presets; light/night preview.
- Overrides are closed, shallow structured JSON. Unknown keys, arbitrary SVG/HTML, external URLs and script strings are discarded, and unsupported object IDs fall back to Auto. Unknown custom subject names retain the deliberately authored generic silhouette.
- The `overlayStudioRecipe` helper projects a sanitized patch onto the stable automatic identity. A preview-specific parameter in the shared renderer allows face-part/hand/scale/prop refinements without modifying the production recipe cache or the canonical Card artwork.
- Undo operates on an in-memory bounded history; **Reset to Auto** adds an undoable empty draft; closing the sheet drops all drafts. The light/night setting is also transient.
- A visible EN/IT notice states **local preview only; nothing saved or shared across devices**. No fake Save button is present.
- Native selects/range input support keyboard/touch. Existing Sheet handles focus trap, Escape/close and focus return; output art is decorative with a spoken preview container. All motion uses bounded CSS keyframes disabled by `prefers-reduced-motion`, without looping or server calls.

## 4. Visual proof — what it is and is not

- `design/v2/page-reference/v2-phase18a-studio-proof.html` and `.svg` are six example compositions generated by the **actual deterministic SVG renderer**: default Auto, face remix, pose/scale/hand, scene/prop/palette, unrecognized name fallback, and night palette.
- They are **static, offline illustration comparisons**, not screenshots of the running React component. They can be inspected without an app build, but they do not certify modal keyboard behavior or mobile layout.
- The source implements the real interactive editor; capture actual browser screenshots when dependencies and device testing are available.

## 5. Isolated performance and asset bounds

Re-run `NODE_PATH=$(npm root -g) node tools/phase18a-metrics.cjs` on a machine with TypeScript installed. Results are at `docs/qa/phase18a-evidence/metrics.json`.

- **1,200** pure SVG render iterations across six draft cases.
- No DOM rendering, GPU work, browser FPS or mobile memory was measured. The report does not extrapolate the Node microbenchmark into a frame-rate guarantee.
- Individual SVGs remain small procedural vectors without raster/media elements, `foreignObject` or SVG turbulence.

## 6. Accessibility and security boundaries

- Closed whitelist with no arbitrary script/CSS/SVG, media or upload control. Nonpersistent `StudioOverrides` is never serialized by the application.
- All controls have visible labels, motion respects the user's preference, and focus trapping relies on the established `Sheet`. Color/illustration never conveys task outcome by itself.
- Intended English and Italian labels appear in the source. Full screen-reader/device validation remains manual.
- No SQL files were introduced. Phase 16A–16C migration/coexistence restrictions remain unchanged.
