# House Care V2 — Phase 11 Routines and Builder Handoff

**Baseline:** `cleaning-duty-phase10-home-redesign.zip` (Phase 10 source snapshot)

**Scope:** V2 Routines library, stable routine artwork, and builder presentation only.

**Status:** Source implementation and available regression checks complete; **full frontend/browser parity remains unverified** because React/Vite dependencies are unavailable in this environment. This is also subject to the still-open Phase 9 live-browser/mobile stabilization gate.

**Explicit exclusions:** No changes to recurrence, tasks, domain types, DataContext, linked every-N semantics, Supabase schema, backups, user theme persistence, art-customization persistence, or any other page.

## 1. User-visible changes

The Routines page now features a compact retro-vector hero with authored sofa artwork and a single Add Routine action; active Regular, active Deep and paused summary counts; search by routine, Action or target; status and Regular/Deep filters; and a responsive list of enriched routine library cards. **Ended** routines remain visible via the status filter rather than being silently hidden.

Every card preserves the full operational information:

- Routine name and Action;
- selected targets and descendant-scoping `+`, plus dynamic target indicator;
- existing recurrence wording, time and fixed/after-completion mode;
- assignment policy/member;
- Regular or Deep channel;
- supplies (inherited Action defaults or explicit override; including no-supplies state);
- active/paused/ended state;
- `Counts toward cleanliness` exclusion, when configured;
- real linked-routine **configuration** (name, every-N *canonical parent triggers*, target, Action, cleaning channel and cleanliness exclusion).

Linked configuration uses an **Extra Care — Configured** treatment; it does not imply that an additional task occurrence has been generated or awarded.

All prior card actions continue to call the original methods: Edit, Pause, Resume, End (with original confirmation), Archive. Existing Action and Supplies navigation remains visible.

## 2. Stable routine artwork (not task editions)

`src/visual/procedural/routine-identity.ts` maps existing Routine/Action/Entity/EntityType information into the current semantic resolver, then creates a **configuration identity** from `routineId + actionId + primaryTargetId + visualVersion`.

It supplies only a fixed non-task library key to the V1 deterministic recipe compositor. The returned artwork identity uses the stable seed; it never receives TaskOccurrence IDs, dates, ordinals, assignees or mutable due/overdue state. The edition is neutral (`house-care`, ordinal `null`), and no linked/earned stamp is inferred from configuration.

`RoutineIdentityArtwork.tsx` displays just the resolved authored vector subject and optional tool, with a lightly printed background. It is deliberately lighter than a full Care Card SVG, because the library can contain many rows. SVG instance IDs are generated by the existing `SvgCharacter`/React `useId()` path. Artwork is hidden from screen readers and is independent of text/status controls. Current semantic theme inks recolor art; no extra theme fields or SVG/recipe persistence was added.

## 3. Builder extraction and functional preservation

`RoutineBuilderSheet.tsx` is extracted from the original nested `RoutinesPage` sheet, preserving its useState fields and its exact create/update input model, including:

1. **What:** Action, Regular/Deep, activity title, cleanliness toggle.
2. **Where:** explicit targets with descendant inclusion, AdvancedTargetBuilder.
3. **When:** fixed calendar vs after-completion; Once, interval, weekday, nth weekday of month; start/anchor/time and next-occurrence preview.
4. **Who:** Me, member, Alternate, Everyone, Unassigned and AdvancedAssignmentBuilder.
5. **Reminder:** none, at due, standard offsets, custom offset, previous day/specific time.
6. **Products:** inherit Action defaults, custom list, none.
7. **Additional activities:** per-N linked configuration using the unchanged component and validation.
8. **More options:** Refresh-to percentage, advanced targets, advanced assignment, simulation, skip/extra/moved dates.

All existing submission validation, exception helpers, scheduler preview and `addRoutine` / `updateRoutine` calls are kept. The new `RoutineBuilderIntro` supplies only retro framing and a read-only live, automatically derived art preview. **There is no Artwork selector or persisted visual override.** The builder uses a key per edited routine to prevent stale form state when switching editing context.

Forms, calendars, recurrence controls, target selection and advanced sections remain plain, high-contrast inputs with no dense halftone overlay. The sheet's keyboard/focus-trap implementation is unchanged.
